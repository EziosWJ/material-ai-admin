# 前端架构说明

本文档说明“本地化智能材料写作平台前端”的项目定位、系统边界和后续业务模块组织建议。

## 项目定位

当前项目是“本地化智能材料写作平台”的前端管理端，基于原 `react-admin` 脚手架复制和改造而来。

项目保留了脚手架提供的后台基础能力，包括登录、后台布局、路由守卫、系统管理、文件管理、日志管理、个人中心、公共表格、公共表单和基础 UI 组件。当前阶段后续业务会围绕材料、片段、来源片段、写作任务、问答和 AI 调用结果逐步扩展。

## 技术栈

- React
- TypeScript
- Vite
- Tailwind CSS
- shadcn/ui 组合方式的本地基础组件
- React Router
- Zustand
- react-hook-form + zod

## 与后端、AI 服务的关系

系统由三个项目协同：

| 项目 | 说明 |
| --- | --- |
| 当前前端项目 | 负责界面、交互、状态展示和 Java 后端 API 调用 |
| Java 后端项目 | 负责业务主控、用户权限、材料主数据、文件上传、写作任务、调用审计 |
| Python AI 服务 | 负责材料解析、片段切分、向量检索、大模型生成等无状态 AI 能力 |

固定调用链：

```text
前端 React 项目 -> Java 后端 API -> Python AI 服务
```

前端不得直接调用 Python AI 服务。所有 AI 相关业务请求必须先进入 Java 后端。

## 前端职责

前端主要负责：

- 登录、退出、登录态展示和路由守卫接入
- 系统管理、文件管理、日志管理等后台能力界面
- 材料列表、详情、上传入口和状态展示
- 片段与来源片段展示
- 写作任务创建、状态展示、结果展示
- 问答过程展示、回答展示、来源片段溯源展示
- AI 调用记录、调用结果、错误信息和审计信息展示
- 前端局部状态、筛选条件、弹窗、表单和加载状态管理

## 前端不负责的事情

前端不负责：

- 直接调用 Python AI 服务
- 写死 Python 服务地址
- 材料解析
- 片段切分
- 向量写入、替换、删除
- 向量检索算法
- Prompt 模板渲染执行
- 大模型生成调用
- AI 调用审计落库
- 业务权限最终判定

上述能力应由 Java 后端或 Python AI 服务承担，前端只通过 Java 后端 API 获取状态和结果。

## 推荐业务模块划分

| 模块 | 说明 |
| --- | --- |
| `material` | 材料管理 |
| `writing` | 写作任务 |
| `qa` | 材料问答 |
| `knowledge` | 片段与来源片段展示，可根据实际业务合并到 `material` 或 `ai` 模块 |
| `ai` | AI 调用记录、模型配置展示等 |
| `system` | 系统管理，继承脚手架能力 |

建议目录：

```text
src/pages/material
src/pages/writing
src/pages/qa
src/pages/knowledge
src/pages/ai
src/api/material
src/api/writing
src/api/qa
src/types/material
src/types/writing
```

如果后续实现中已有更适合的组织方式，应优先保持项目现有风格，不为了目录建议做无关重构。

## API 调用边界

- 页面通过 `src/api` 中的模块调用 Java 后端 API。
- `src/lib/http.ts` 是统一 HTTP 请求封装。
- 领域类型优先放入 `src/types`。
- 页面组件不应直接散落 `fetch` 调用。
- AI 相关业务 API 也必须体现为 Java 后端 API，例如写作任务、问答请求、来源片段查询、AI 调用记录查询。
- 不允许新增直连 Python AI 服务的请求模块、环境变量或硬编码地址。

## 来源片段展示约定

来源片段用于展示写作任务或问答结果的参考来源和溯源信息。前端展示时应优先包含：

- 来源材料名称或材料 ID
- 片段序号
- 片段正文摘要
- 相关度或置信信息
- 与当前生成结果或回答的关联关系

展示要求：

- 对外文案使用“来源片段”。
- 相关度可用于排序、过滤、调试或低置信度提示，不一定直接展示给最终用户。
- 来源片段展示应服务于可追溯、可核查，不应喧宾夺主。
- 如果数据来自 Java 后端，前端只负责展示，不重新实现检索逻辑。

## 后续开发建议

- 新业务页面优先复用现有后台页面骨架和公共组件。
- 新增菜单和路由时，沿用 `src/router.tsx` 与 `src/config/navigation.ts` 的现有组织方式。
- 新增 API 时先明确 Java 后端接口边界，再在 `src/api` 中封装。
- 新增类型时优先按领域放入 `src/types`，避免页面内重复定义大型类型。
- 保持领域术语统一，优先参考 `docs/domain-language.md`。
- 通用后台能力不要随业务开发随意重构。
- 不因单个业务页面引入新依赖、复杂状态框架或大型 UI 框架。
